# 已标记根系仍被漏检：核查结果

例图定位为0353-1-B3、T1，500×500像素训练图。与当前共有视野RGB的对应区域逐像素一致。

- 上传JSON中66张图的binary mask均与实际训练文件逐像素相同；temporal层与binary mask的根系支持域也完全一致，没有漏读到另一层的根系标记。
- 重新划分后，新增66张中52张用于训练、14张用于内部验证；本例属于训练集，不能将本例漏检解释为未加入训练。
- 当前共有视野预测采用310图固定100轮训练中选出的第32轮权重。该例4153个标记根系像素中识别2056个、漏2097个，召回49.51%，Precision84.47%，Dice62.43%。这些是本例已参与训练区域的拟合诊断，不是独立验证成绩。
- 阈值从0.5降至0.2，召回仅升至55.02%，Precision降至66.87%；低阈值无法完整恢复漏根。
- 使用同一500px裁剪单独重新推理：旧V35召回43.15%，新第32轮48.81%，第100轮48.23%。与整视野滑窗上下文有小幅差异，但两种输入都存在明显漏检；改用第100轮也未解决。不能直接用这些裁剪数值替代整视野数值。
- 每张500px训练图每轮只随机取一个原尺寸256px窗口，没有保证整张标记覆盖。按种子回放所有训练裁剪，最终Python随机状态与实际第100轮训练状态完全匹配。选出的第32轮之前，本例806个标记根系像素（19.41%）未被采样；100轮后仍有348个（8.38%）未被采样。漏检的2097个像素中，只有162个属于第32轮从未采样的区域，因此覆盖不足确实存在，但不能解释全部漏根；训练过的细根也存在拟合不足。
- 最终两类时序前景严格等于V35前景，V90只给检出的根分时序类别，因此V35漏掉的根不会被当前时序流程补回。

训练把标记作为优化目标，并不会把已标记像素原样存入模型或自动覆盖预测。加入数据和完整识别是两件不同的事。本例证明当前细根学习仍不充分。上一轮连接和像素一致性核查不能代替逐图漏检核查。

下一版应优先保证训练集500px标记的重叠分块完整覆盖，加强细根与漏检区域采样，并在内部验证集选择兼顾根系Recall、Precision和连通性的方案；在控制假阳性的前提下验证改进后再接入V90。现有权重及预测保留，本次仅诊断，没有重新训练或替换标签。
